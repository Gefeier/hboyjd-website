# Interactive drop-side exterior sample

- Page: `/vehicle-experience.html`
- English UI: `/vehicle-experience.html?lang=en`
- Reference specification page: `/vehicles/EHJ9400LB.html`
- Three.js: pinned r182 / 0.182.0, MIT, locally vendored under `assets/vendor/three-r182/`.

## What is represented

This is real WebGL geometry with free orbital rotation, zoom, four camera focus
points and independent painted-body materials. It is a simplified exterior
illustration of a straight drop-side semi-trailer with six sideboard sections,
a tall front board, three axles and twelve tires. It is **not** an exact CAD,
scanned model or certified configuration of EHJ9400LB. The visible UI makes that
distinction in both languages. The general shape uses the public product imagery
and the model's published specification page as references. No engineering file,
internal structure, fastener detail or production process is included.

The photo view uses the existing public same-series sideboard photo at
`assets/images/products/fence/01.webp`, with a same-series reference label. It
shows a different deck variant and must not be relabeled as this exact model.

## Interaction and loading

The initial page shows a photo-backed launch screen. Three.js and OrbitControls
load from the same origin only after a visitor requests 3D or selects a 3D option.
No dependency or model is fetched from a third-party CDN at runtime.

- Drag / one-finger movement: orbit.
- Wheel / pinch: zoom.
- Numbered points or panel rows: approach the sideboards, deck, axle group or legs.
- Plus/minus controls: zoom; Whole vehicle: reset.
- Focused canvas: arrow keys orbit, `+` / `-` zoom, Home resets.
- All hotspots and color options are ordinary keyboard-accessible buttons.
- Changing language updates text and URL without recreating the camera or model.
- Paint changes affect only body materials; tires, wheel rims and deck keep their
  own materials. Choosing a color while viewing a real photo returns to 3D.
- No auto-rotation. Reduced-motion preferences disable camera transitions.
- Rendering is requested only on interaction, resizing and brief camera moves.
  Device pixel ratio is capped at 1.5 on small screens and 2 on desktop.
- Unsupported WebGL, import failure or context loss displays the reference photo.

## Integration

Add links from the catalog and EHJ9400LB detail page to the sample route. For
English detail pages, include `?lang=en`. This page is an independent bilingual
experience and is not generated by `scripts/build_english.py`.

When an approved public 3D display asset becomes available, replace the geometry
construction in `createViewer()` and realign the four points/camera targets.
Do not directly publish an internal engineering model. Keep the original model
specifications and enquiry link as the product source of truth.

## Verification

Run `node --check vehicle-experience.js`. Browser checks should cover desktop and
375 px layouts, language changes without camera reset, all four focus points,
body color changes, keyboard controls, photo/3D mode switching, reduced motion
and the no-WebGL fallback. Source links and the local dependency paths can be
checked without loading an external service.

Official API reference: https://threejs.org/docs/pages/OrbitControls.html
